# DingDong Studio

Mac mini 上的插件任务与推送中心，手机端通过 DingDong 接收。双击 dist/MiniPush-darwin-arm64/MiniPush.app 打开。

## 第一版

- 叮咚自建中转：可配置 IP、端口或域名、发送密钥、消息来源与静默保存，支持图文离线阅读与手机保存确认
- 兼容原有 Server 酱³ / Turbo 渠道
- 统一 OpenAI Responses AI 配置，可选择模型和输出上限
- 从本机文件夹导入 JavaScript 插件，自动生成插件配置表单
- 每个任务选择插件、接收渠道、AI 配置和发送条件
- 手动、每天定点（可添加 1–24 个时间点）、固定分钟间隔，全部使用北京时间
- 内容变化去重，运行记录，手动取消，普通插件 120 秒、工具调用插件 300 秒执行超时
- 关闭窗口仍在后台运行，Cmd+Q 完全退出，可选登录时启动

## 手机管理订阅

升级叮咚服务器和 Android App 后，在 Studio「应用设置 → 允许手机管理订阅」选择一个叮咚渠道。手机沿用同一服务器的接收密钥，从左侧菜单进入「Studio 订阅」。默认关闭；选择「关闭手机管理」可停止处理手机控制请求。

手机可新增、编辑、启停、删除 B 站/贴吧/X/小红书内置订阅及统一推送，修改兴趣规则、贴吧列表、内容源、已有 AI/推送渠道、每日多个时间点或执行间隔。账号登录、插件安装、API 密钥配置和自定义代码插件仍在电脑端完成；B 站账号与 UP 主通过 UID 填写。时间均为北京时间。

电脑需在线且 Studio 保持运行，无需额外开放电脑端口。一个叮咚服务器同时连接一台 Studio。持有该服务器接收密钥的手机可管理这些订阅。更换服务器或关闭连接后，服务端在线状态约 15 秒失效。修改须经 Studio 确认，离线时不会积压控制操作；超时后先刷新核实是否已保存。电脑和手机同时编辑时通过配置版本拒绝旧设置覆盖。

中转只在内存中暂存白名单订阅配置和短期命令，不上传平台 Cookie、API/发送密钥、历史消息、插件状态或本地路径。`src/mobile-control.cts` 负责快照裁剪、配置冲突检查与出站同步；手机操作调用与桌面相同的任务保存/删除处理器。开关保存在既有设置文件中，旧配置默认关闭。

## 开发

Node.js 24（构建脚本使用 Node 原生 TypeScript 类型擦除）；Electron 应用运行的是编译产物。

```sh
npm install
npm run typecheck
npm start
npm test
npm run test:ui
npm run format:check
npm run package
```

源代码使用 Electron 主进程、隔离的界面进程、独立的插件子进程。密钥使用 Electron safeStorage 和 macOS 钥匙串支持的加密持久化，界面只收到是否已配置。数据位于 Electron userData 目录，一般为 ~/Library/Application Support/MiniPush。更新应用保留数据。

全项目源码使用 TypeScript，开启 `strict`、未使用变量/参数检查和 `noEmitOnError`。主进程、预加载、插件与测试使用 `.cts`（编译成 CommonJS `.cjs`），界面使用 `.ts`（编译成浏览器 ES Modules `.js`），构建脚本使用 `.mts`。`.cts` / `.mts` 都是 TypeScript，不是遗留 JavaScript。

- `src/types.cts`：任务、配置、消息、插件上下文、数据源、AI 工具和运行记录的共享类型。
- `src/ipc.cts`：主进程与界面共享的 IPC 参数和返回值契约。
- `src/ui/`：界面与类型化 DOM/表单访问；`global.d.ts` 声明预加载 API。
- `examples/`：可编辑的 TypeScript 插件示例；`tests/`：回归测试和编译期契约验证。
- `scripts/build.mts`：先完成四组类型检查，再生成代码并复制 HTML、CSS、图标和插件 manifest。
- `build/`：自动生成的运行目录，可重新生成，不手工编辑、不纳入源码管理。`dist/` 是应用打包产物。

`npm start`、`npm test`、`npm run test:ui`、`npm run package` 均先构建。`npm run typecheck` 只检查、不生成代码。打包从 `build/` 读取运行文件，排除测试；不会将源码或开发依赖装入应用。现有用户数据目录、加密密钥、登录会话、任务字段和插件 `index.cjs` 运行协议保持兼容。

测试按用途放在 `tests/`：根目录是单元与服务回归测试，`tests/e2e/` 是 Electron 界面验证，`tests/helpers/` 是模拟模型。`npm run test:ui` 顺序运行所有界面验证，使用独立临时数据与模拟推送，不发送手机消息。截图和测试数据写入系统临时目录，执行结束自动清理；设置 `MINIPUSH_KEEP_TEST_ARTIFACTS=1` 可保留并打印路径以便排查。一次性接口探测、旧版本备份和研究下载不要放进项目源码目录。测试文件不进入应用安装包。

## 编写插件

复制 `examples/hello` 到 `examples/你的插件`，修改 `plugin.json` 的唯一 id、名称、版本和字段，编写 `index.cts`。运行 `npm run build` 后，在应用「插件 → 导入插件」中选择对应的 `build/examples/你的插件` 目录。应用「打开示例文件夹」也打开编译后的可导入目录。运行时只依赖插件目录内的文件；共享类型用 `import type` 引用，不能从插件外部导入运行时辅助函数。已有 ID 的插件需先删除引用任务并移除旧插件，避免静默替换正在执行的代码。

plugin.json 必须有 apiVersion: 1、id、name、version、entry: "index.cjs" 和 fields 数组。字段类型支持 text、textarea、number、boolean、forums（1–5 个 {name, filter} 配置），字段可包含 required 和 default。插件目录最多 20 MB，禁止符号链接。

源码 `index.cts` 使用 `export async function run(context)`，编译后的 `index.cjs` 导出相同入口。context 提供：

- task：任务的 id 和 name，供插件使用任务名作为通知标题

- config，任务保存的字段值
- state，上一次成功执行后的插件状态，用于保存已读文章 ID
- now，本次执行的 ISO 时间
- ai.generate(prompt)，调用任务选择的 AI，返回文本。每次执行最多 5 次调用
- ai.respond({instructions, input, tools})，共享的 Responses 函数调用接口，返回完整 output 项；需声明 ai.tools 能力，每次任务最多 35 轮。插件只负责注册和执行自己的工具，无需接触 Key 或实现 HTTP 调用。
- log({forum, tool, status, detail})，记录实际工具操作与结果；不保存模型内部推理或密钥。

Node.js 内建 fetch 可读取 RSS 或 API，无需访问 AI Key。

```js
exports.run = async function run(context) {
  const body = await context.ai.generate('用一句中文介绍 RSS')
  return {
    message: { title: 'RSS 简介', body },
    state: { lastRun: context.now },
  }
}
```

无新内容时返回 { message: null, state: {...} }。消息支持 title、body、short（预览），format 可选 markdown（默认）/html/text。叮咚优先使用可选 articles 结构化内容，其他渠道继续使用 Markdown body。状态仅在成功投递或跳过时提交，推送失败保留旧状态。比较完整消息内容决定是否去重，动态时间会令消息不同。

导入的 Node.js 插件具有当前用户的文件与网络权限。子进程用于故障隔离，并非安全沙箱。只导入自己编写或信任的插件。应用不通过插件上下文传递渠道或 AI 密钥。

## 调度与故障行为

应用运行且 Mac 唤醒时，每 5 秒检查到期任务。同一任务不会并行运行。重启或唤醒后的逾期任务最多补跑一次，不补齐全部漏跑次数。先持久化下次时间再执行，避免短时间重试风暴。

推送服务接受请求后，记录为「已提交推送」。手机是否展示通知取决于客户端。网络超时可能发生在服务实际收到消息之后，重试可能重复投递。叮咚网络错误和 408/429/5xx 自动重试最多 3 次，同一轮复用消息 ID 和完全相同正文；运行记录可查询 queued/received。跨次手动重跑属于新执行，提交结果不明时应先查送达状态，避免再次发送。其他渠道仍采用手动重试。运行中退出会记录中断。

## AI 额度

Pro 订阅符合条件且已关联 API 组织时可领取 API 额度，实际额度以 OpenAI 控制台为准。AI 测试和插件调用会消耗 API 额度。自定义基础地址必须实现 Responses API。

## B 站关注视频插件

在「插件」中安装 B 站插件，再点「登录与订阅」。登录窗口是 B 站自身页面，可用 B 站 App 扫码；完成后刷新登录状态。登录保存在独立的本机 Electron 会话，应用不要求手动复制 Cookie，也不把 Cookie 传给插件或 AI。

读取关注列表后勾选 UP 主（每个任务最多 50 位），可先预览最近两页关注视频动态，再配置推送渠道、执行时间、关键词和可选 AI。默认建议每 30 分钟检查一次。每次最多发送 1–20 条，未发完的结果保留到下一次。AI 只整理标题和简介，不代表已观看或转录完整视频。

首次运行只建立基线，不补发历史视频。更换账号、UP 主选择或关键词后重新建立基线。推送失败不推进检查记录。账号失效、切换账号、平台拒绝请求或响应结构变化会记为失败，不会当作“没有更新”。本机退出登录不操作远端账号，已有任务继续保留但无法采集，需重新登录或暂停任务。

采集使用 B 站网页使用的登录与读取接口，并非已获审批的开放平台接入；平台改动或风控可能影响可用性。每次最多扫描 5 页关注视频动态，超出会显式报错并保留旧进度，避免静默漏掉中间页；长期离线或关注量大时需缩小订阅范围、提高检查频率，必要时重新创建任务以重建基线。当前只支持一个本机登录账号。

该插件源码在 `examples/bilibili`，构建后从 `build/examples/bilibili` 单独导入。manifest 声明 capabilities: ["bilibili.read"] 后，插件可通过 context.sources.bilibili.feed({accountMid, since}) 调用宿主的数据读取服务，取得标准化视频信息（每次任务最多调用两次）。登录窗口与账号访问由宿主维护，筛选、摘要、去重和消息格式在插件脚本中实现。

## 贴吧兴趣精选（插件 4.0.0）

职责是根据个人兴趣挑选值得阅读的内容，解释推荐理由并整理要点。贴吧插件不再提供全部新帖通知或全量新帖摘要模式。候选采集、兴趣筛选和推送各自分开。

在「插件 → 配置贴吧订阅」填写总过滤说明，添加 1–5 个贴吧，每个贴吧分别填写吧名和可选的本吧过滤说明，并选择已有 AI 配置。总说明作为默认；本吧说明补充要求，冲突部分以本吧说明为准，未冲突的总规则继续生效。本吧说明留空则继承总规则。可先「查看候选」或「预览 AI 精选」；AI 预览消耗所选服务额度，但不发送消息、不提交筛选记录。任务也可直接在任务列表编辑。

可以直接写「关注漫画讨论，回帖数超过 20，最近三天发布；标题含糊时先读首楼」。无需新增回帖数或时间筛选表单。AI 根据有效规则选择工具并生成参数：

- list_candidates：查看当前候选的标题、摘要、回帖数和发帖时间。
- filter_candidates：由程序执行回帖数、距发帖小时数、发帖时间的比较，支持大于、至少、小于、至多、等于、不等于及 AND/OR。未知值不会通过硬条件；多次调用只会收窄候选。
- read_posts：按需读取首楼（每次最多 3 篇，每吧最多 6 次），供进一步判断；不读取评论或识别图片。
- submit_selection：提交入选 ID 与分数。程序拒绝未知 ID、已被硬条件排除的帖子、低于门槛或超过数量上限的结果。无法满足要求的能力会明确报错。

每轮查阅机制：

1. 贴吧插件保留发帖时间和最近回复两路列表，各取 2 页，合并最多 80 条。另用 1 次 AI 按有效兴趣规则生成最多 3 个吧内查询，按时间倒序各取 20 条；交错选择最多 6 篇未推送的新搜索候选，补读首楼和回帖数，合并最多 86 条再筛选。可以关闭补充搜索，列表来源始终保留。不覆盖全吧历史；每吧最多 6 轮筛选、两个吧并发，整个任务最多 35 次 AI 请求和 300 秒。
2. 每轮重新判断当前尚未推送的候选，不再复用旧版的 7 天筛选缓存，以便回帖数增长和相对时间条件立即参与本轮判断；因此通常比旧版单次文本筛选使用更多 API 请求。AI 只拿到列表摘要，以及它实际调用工具读取的首楼文字（最多 6000 字），不会默认声称读过评论或图片。
3. 保留每吧最近 2000 个已推送 ID；旧任务的已推送记录继续生效。规则变化不重发已推送内容。上轮入选但未发的帖子，也必须出现在本轮候选中并重新满足规则，才能发送。
4. 各吧结果按相关度合并，所有贴吧合计默认最多 3 条（可设 1–5 条）。确认首楼来源后生成原文推送；读取过程中获得更新的回帖数时，会重新执行已应用的硬条件。
5. 没有候选时不调用 AI；无匹配时不推送。错误、超时、取消或投递失败不提交新的去重记录。AI 不能直接发送通知、执行命令或访问任意地址；它只能请求本插件提供的工具。
6. 预览和运行记录中可展开「工具执行过程」，查看实际过滤条件、剩余数量、读取过的首楼 ID 和提交结果。日志不加入手机推送。预览不发送通知，也不修改检查点。

新建向导默认每天北京时间 20:00，可改为每天多个时间点（如 04:00、12:00、20:00）或固定间隔。每日时间按先后排序，不允许重复；旧的单时间配置继续兼容。Mac 休眠/应用退出期间不运行，恢复后对当前候选精选一次，不能保证覆盖离线期间全部帖子。

推送使用 Markdown：帖子标题直接链接到贴吧 App，来源使用引用格式，正文仅保留楼主首楼原文节选（最多约 220 字、4 段）和可选首图。长首楼优先在句末截断，注明点击标题查看全文；不使用 AI 摘要代替正文。通知标题使用任务名称（服务标题长度上限为 100 字符）；不展示精选数量、推荐理由、处理统计、底部说明或网页备用链接。正文使用二级标题链接 `## [帖子标题](贴吧地址)`，帖子之间使用 Markdown 分隔线，来源不包含发帖人。Server 酱 App 自带标题横幅没有公开的隐藏 API；横幅文字由任务名称提供，不能更改客户端样式。App 链接采用 com.baidu.tieba://unidispatch/pb?tid=帖子编号，参考第三方贴吧客户端的链接解析实现。Server 酱和手机系统能否转交该 Scheme 仍需真机验证；scopen:// 仅启动包名并传 extras，不能直接假设它会打开具体帖子。旧消息链接不会随更新改变。

信息源仍参考 RSSHub、aiotieba、MediaCrawler；具体版本、采用范围和许可见 THIRD_PARTY_NOTICES.txt。公开贴吧当前无需登录，接口变化或访问限制会显式报错。

插件源码在 examples/tieba。声明 capabilities: ["tieba.read", "ai.tools"] 后，通过 context.sources.tieba.feed({target: '吧名', mode: 'interests'}) 获取 {mode, entries, target, scopeDescription}。另可通过 context.sources.tieba.post({id}) 读取首楼。`agent.cts` 管理工具定义、参数验证和调用循环；`index.cts` 负责去重、跨吧合并和排版；宿主负责共享 AI 接口、取消、预算与推送。

## X 兴趣发现（插件 1.0.0）

在「插件」安装 X 插件，点「登录与兴趣发现」，在 X 官方窗口登录，再刷新登录状态。填写兴趣说明并选择共享 AI 配置，即可预览。比如：「寻找 AI 开源工具和模型发布，最近 7 天、回复超过 20，排除广告和课程推广。」预览不发送消息、不创建任务、不修改已推送记录。确认内容后「配置推送任务」，选择渠道和每日多个时间点、固定间隔或手动执行。

X 插件先读取关注时间线最多 40 条，再用 1 次 AI 拆分最多 3 个独立主题查询，同义词可用 OR，不同兴趣不强制交集。每组各取 Latest 和 Top，交错合并去重并保留来源。关注流和搜索可分别关闭，至少启用一路。筛选阶段使用 filter_posts 执行互动数和时间条件，按需读取原帖，最后提交入选 ID；数值条件依旧由程序执行，未知值不通过。默认提示近 7 天，实际查询和条件可在工具过程查看。

计划阶段最多 6 次搜索，每次首批最多 30 条；与关注流合并后候选最多 120 条。筛选阶段可额外补搜 1 次，总采集最多 8 次（含关注流）。搜索和关注流均不翻页、不保证全量覆盖；关注流排除广告和转推。模型先看每篇前 400 字，最多读取 3 篇详情；规划 1 次、筛选最多 8 轮 AI 请求，整轮 300 秒。详情仅含当前返回的原帖和同作者讨论串片段，不读取他人评论、不识别配图或视频。推送 ID 去重行为保持不变。

推送标题使用任务名。正文使用原文短标题（二级标题，优先保留 64 字内完整首句，超长标题节选约 42 字）、最多约 400 字原文节选与可选首图；完整作为标题的原文开头不再重复。引用内容置于配图之后，多帖间有分隔线，不添加 AI 推荐理由或作者说明。按接口 entities 展开外链、移除图片占位短链，保留视频和未知链接。标题使用 `twitter://status?id=帖子ID` 直接请求 X App 打开帖子，底部保留 HTTPS「网页查看」。手机客户端是否接受 Scheme 仍需真机确认；已有消息不会随格式更新而改变。

登录与读取分开：Chrome 或内置窗口仅用于主动登录，任务通过后台 HTTP 请求读取 SearchTimeline / TweetDetail，不打开搜索网页。可从常用 Chrome 授权导入 x.com 会话，凭据使用 Electron safeStorage 加密保存，随后立即断开浏览器。导入后可关闭远程调试。旧版本专用 Chrome 的登录可点击「刷新登录状态」迁移一次。Cookie 不交给插件或 AI。

后台沿用系统 HTTP/HTTPS 代理。公共接口参数缓存 6 小时，更新失败最多复用 7 天内缓存；交易签名使用 MIT 开源库 x-client-transaction-id。接口参数失效时刷新重试一次，限流和登录错误不会反复重试或退回浏览器采集。这不是 X 官方开放 API，平台改版或验证可能导致失败。登录状态只表示保存了凭据，搜索才验证可用性。退出本机登录清除应用凭据并取消读取，不删除任务或退出常用 Chrome。

源码在 `examples/x`，声明 `capabilities: ["x.read", "ai.tools"]`；宿主提供 `context.sources.x.search({accountId, query, sort})` 与 `detail({accountId, id})`。工具仅能读取和筛选，不能自行发送消息或执行任意命令。调研来源见 `THIRD_PARTY_NOTICES.txt`。playwright-core 仅用于主动登录与授权会话导入；后台请求使用 undici 和可取消、可超时终止的独立 utilityProcess。

## 叮咚接入与 HTML 正文

协议参照 Morgiana-V3/dingdong 提交 82cb993b21798f1b93efb1caadbc2c19ea570cf9。推送渠道选择「叮咚 App · 自建中转」，填写服务器基础地址（例如 http://192.168.1.10:8080）、DINGDONG_SEND_TOKEN、来源名称。接收密钥和服务器 SSH 密码都不需要填入本应用。更换地址或渠道类型后必须重新输入发送密钥，避免旧密钥被发送到新地址。

发送使用 POST /v1/messages 和 Bearer 鉴权，禁止跟随重定向。queued 仅表示服务器收下，received 表示手机已保存，不代表已读。运行记录和渠道测试均保存消息 ID，可点「查询送达状态」。保存确认不需要占用手机的 WebSocket 接收连接。当前协议为单手机；换手机和服务器迁移遵循叮咚项目文档。

X、贴吧、B 站插件额外返回 articles：kind、title、body、url，以及可选 source、images、quote、truncated、duration、publishedAt（Unix 毫秒）。正文是原文，不是 AI 推荐文案。宿主生成 HTML/CSS，保留内容层级、原帖入口、配图和引用；长文用无需脚本的 details 展开；展开后隐藏摘要和按钮，显示连续全文。B 站显示接口提供的封面与时长，不嵌入播放器、不声称读取了完整视频。该结构不是任意远程模板执行器，文字经过 HTML 转义。原有自定义消息插件可继续输出 Markdown，也可自行提供 format:html 和静态 CSS。

新 HTML 不重复输出顶部任务名大标题；任务名只用作消息列表和通知标题。系统深色模式通过 prefers-color-scheme 适配。X 仍使用 HTTPS。贴吧标题保留 com.baidu.tieba://unidispatch/pb?tid=帖子编号，Mac 预览点击时使用网页地址。叮咚 0.1.0 阅读器只放行 http/https/mailto，因此该版本手机端仍会拦截贴吧 App 链接；需要手机端支持后才能直达，此次未修改手机端。

图片发送前转成 data URI。最多处理 80 个不同的配图地址、40 个不同的贴吧表情地址，每张下载上限 8 MB；按唯一图片地址分配整份文档预算，重复图片复用，表情占较小权重，剩余空间可供后续图片使用；长图同时限制长边并按需降低尺寸和质量，适配 1 MB 正文限制。小动图保留，超预算动图不转成误导性的静态图。图片失败时保留可见说明和原帖入口，投递结果分别注明配图与表情缺失数量、来源域名及 HTTP/预算/格式等原因，表情失败退回名称。字体、脚本、外部 CSS 和视频不远程加载。HTML 带限制性 CSP；Mac 的「预览 HTML 正文」窗口禁用脚本与 Node，手机实际画面仍以其 WebView 为准。

预览会重新生成并读取图片，用于检查排版；不是服务器已投递正文的逐字节存档。为了节省空间，运行记录保留原始内容和图片地址，不重复保存大块内嵌图。手机收到的文档则可离线阅读。

贴吧 1.3.0 保留首楼表情编号、名称和原文位置：支持常见泡泡与已知表情包资源族，表情以 24px 行内 CSS 背景随正文内嵌，小 GIF 保留动效。未知编号或下载失败保留名称，不用普通 Emoji 替代。长文展开不截断表情；自定义贴图仍按原帖图片展示，每帖最多 4 张。

## 统一推送

内置「统一推送」可选入 1–8 个已有任务作为内容源，复用每个来源的插件配置、AI 和去重记录。来源只执行采集，汇总按自己的时间和叮咚渠道发送一份 HTML。正文默认 15px、行高 1.65，帖子标题 20px，保留贴纸主题。

启用汇总会关闭所选来源的独立调度，并禁止单独执行、重复归属到另一个启用中的汇总。原任务和原时间配置仍保留；停用汇总或移除来源后，可手动启用来源恢复独立执行。来源被引用时不能删除，汇总运行时不能编辑来源。允许勾选停用的原任务，停用只表示不独立调度。

执行时锁定所有内容源，逐个调用原插件；全部无新内容则跳过。单个来源失败会记录来源错误并继续其余来源，汇总标记为「部分完成」；正常来源有内容就合并发送，成功投递后仅提交成功来源的状态。失败来源进度保留，下轮重试，已成功发送的来源不会因此重复发送。成功来源都无新内容时不发通知，但可提交其基线；全部来源失败则整轮失败。用户取消或最终投递失败仍不提交任何来源状态。无内容的首轮基线也会在整轮成功结束后保存。当前不支持嵌套汇总，不另加一次 AI 总结。

汇总消息使用 sections（name、message），结构化 articles 保留原文与配图，取消任务分组，按原帖 publishedAt 从新到旧混排；缺少时间的条目保留相对顺序放到末尾，不用采集时间冒充发帖时间。普通内容在卡片上保留来源；普通 Markdown、文本和 HTML 内容统一排版，通用 HTML 的原有 class/id/style 与样式表会移除，避免覆盖整份汇总。整份文档仍受 1 MB 上限约束，超过限制会失败并保留检查点，不偷偷丢掉某个来源。

贴吧表情在发送前由临时 img 转成带 data URI 的 CSS 背景 span。叮咚 0.1.0 图片查看器只收集 img，因此表情不会成为上下切换的大图；普通原帖配图仍参与图片查看。该方案不需要修改手机 App，也不依赖远程图片或脚本。

检索策略保留在各插件的 retrieval.cts 中。主程序只提供固定平台读取能力、共享 AI、执行上限、日志与调度，不生成关键词，不替插件决定来源；统一推送只合并插件结果。查询、各路数量、合并结果与入选来源仅显示在桌面执行记录，不加入手机正文。来源读取失败由汇总隔离，错误保留在桌面运行记录；去重记录仅在对应内容成功投递后提交。

## 小红书兴趣发现（插件 1.0.0）

在「插件」安装小红书插件，打开「登录与兴趣发现」，使用手机小红书 App 在官方窗口扫码确认，再刷新登录状态。填写兴趣、选择共享 AI，可以先预览，再配置来源任务。新任务默认不单独定时发送：在现有「订阅汇总」中选择它，跟随汇总时间发送到叮咚。未登录或预览失败时不要把账号 ID 随意填写为其他账号。

第一版由插件自身组合两路来源：独立读取推荐流首屏最多 30 篇，再由 AI 将兴趣拆成最多 3 条独立关键词，分别读取综合搜索首屏最多 30 篇。交错合并、按笔记 ID 去重，排除已推送内容后最多保留 90 篇。推荐流与关键词搜索可分别关闭，至少保留一路；不读取关注列表、不自动翻页，不保证完整覆盖。默认提示筛选近 30 天，用户明确时间范围时按要求执行。

AI 先按候选标题选择最多 6 篇读取正文，再通过 `filter_notes` 执行点赞、评论、收藏数与距发布时间的硬条件，最后最多提交 3 篇。所有提交笔记必须读过详情、满足程序过滤条件；`1.2万` 等缩略数按未知处理，未知值不通过数值硬条件。数值与时间条件仅支持全部满足的组合。AI 仅分析文字，不识图、观看视频或读取评论正文。每轮规划 1 次、筛选最多 8 轮，整轮 300 秒。

参考 xiaohongshu-mcp 的页面状态读取思路，以原生 TypeScript 实现。官方登录窗口可见，定时采集在独立的后台网页窗口执行，不依赖另装 MCP 服务。小红书会把部分海外代理流量重定向至 Rednote，因此此连接固定直连国内站，其他平台及系统代理不变；不支持 Rednote 账号。登录状态由本机独立 Electron 浏览器资料持久化，不把 Cookie 交给插件或 AI。退出本机登录清除该资料。页面结构变化、登录过期、访问验证和网络失败会显式报错，不绕过验证。搜索只在有候选，或首屏接口明确成功且确认空结果时完成，避免把请求未完成误作没有内容。

叮咚接收原文标题、正文、最多 4 张配图和原帖 HTTPS 地址（保留必要的 xsec_token），以红色便签卡片呈现，长文沿用展开机制。对原生组件无法解码的大体积 WebP 图片，使用禁止联网的本地 Chromium 文档转为预算内 JPEG，再随 HTML 离线嵌入。标题可打开网页，是否唤起小红书 App 由手机端链接处理决定；不声称强制直达 App。AI 不撰写推荐理由。加入汇总后与其他来源按发布时间混排；单个来源失败不会阻止其他正常来源发送，失败来源不推进去重记录。只有推送接受后才提交已发送 ID。

参考范围与许可见 THIRD_PARTY_NOTICES.txt。源码在 examples/xiaohongshu；声明 `xiaohongshu.read` 和 `ai.tools` 后，通过 `context.sources.xiaohongshu.feed/search/detail` 获取受限数据。宿主只提供读取适配、共享 AI 和执行预算，检索与筛选逻辑留在插件内。

多图采用缩略图网格：2 张并排、3 张三列、4 张两行两列，单图维持原有展示。网格只在 CSS 中裁切，内嵌图片保留完整画面，继续使用手机端已有图片查看功能；没有新增网页脚本或改动手机 App。小红书正文里的 `#话题[话题]#` 和连续普通话题转为轻量标签，隐藏 `[话题]` 标记，不改写其他原文；长文截断不切开话题标记。历史手机消息不会被自动替换，应用预览会用新规则重新生成。
